# Workspace LLLM bridge

The independent app is `/apps/lllm/minamomura`. It uses the same Site identity as Plotline and checks current `account_memberships` on every request. Only workspace ID `0279e5f9-6122-4fb9-90ff-b9073a9fc7c1` is eligible. Its owner can disable the extension; names never grant access.

`lllm-connector.cjs` is installed as `C:/AI/ControlPanel/workspace-lllm.cjs`. The existing controller starts it and makes outbound HTTPS requests to `https://game-canvas.app/api/lllm-connector`. No inbound port, public model API, browser mesh membership, or direct browser connection to the PC is required. Existing Windows login supervision restarts the controller. It can start on loopback when Meshnet is absent.

The connector's token and RSA private key live in `state/workspace-lllm.dpapi`, protected with Windows DPAPI CurrentUser. They are configuration credentials, not conversation storage. Production has the matching `LLLM_CONNECTOR_TOKEN` secret and SPKI base64 `LLLM_PUBLIC_KEY`. Only the public key reaches browsers. Changing credentials requires redeploying the Site environment and restarting an idle controller.

Every browser request uses a fresh AES-256-GCM key wrapped with RSA-2048 OAEP SHA-256. The job ID and direction are authenticated as GCM additional data. The connector validates an exact HTTP route allowlist, inserts the controller token in memory, and assigns a distinct virtual peer to each account. The existing text encryption and encrypted image memory store remain in use. Registered persistent image keys and desktop administration are excluded. Workspace users cannot read one another's image jobs, files, queue tickets, or text sessions.

D1 contains only encrypted transport chunks and request metadata. Pending work expires after 20 minutes; completed results expire after 2 minutes and are deleted after browser receipt. The connector sweeps expired rows while online and on reconnect. Expired results cannot be read even when the PC is offline. Interrupted claimed operations fail after restart and are never replayed automatically. Revoking membership or disabling the extension blocks retrieval and aborts active transport on its next poll.

Conversation and image data are not automatically written to the PC filesystem. Existing encrypted image output is held in RAM and expires after receipt. Text workers overwrite explicit buffers and stop the text backend after replies. Browser contents and keys stay in memory; no localStorage, IndexedDB, Cache API, service worker, or sessionStorage is used. HTML, app code, API responses and error responses carry `no-store`. App entry clears its origin's HTTP cache to remove older cached assets. Script/style assets use dynamic routes because the static asset hosting layer overrides cache headers. User-requested downloads are explicit. Model files and GPU compilation caches are separate existing runtime resources. OS paging, crash dumps and browser internals cannot be guaranteed by HTTP headers or JavaScript.

Text responses are delivered once the protected backend has completed cleanup. Image progress uses encrypted HTTP status polling rather than WebSockets. Reference images and results are split into bounded encrypted chunks. No payloads, keys, prompts, replies, or image bytes are logged by the connector.

Validation: `node --test tests/lllm-relay.test.mjs tests/auth-security.test.mjs tests/phase2-security.test.mjs tests/version34-workspace-deletion.test.ts`. Build with the project's Vinext tool. Full-project TypeScript checking has pre-existing errors in Confluence and older tests; the new extension files pass the type check.
